## Q1. HOW THE CONTROLS ARE CONSTRUCTED (file:line)
================================================================================

There are two distinct control types, built very differently. Both are 20 combos = 40 total.

### CHANCE control (gate4) — "same data, broken pairing"
- Selection: `select_chance_controls` (analysis.py:1711). Draws **20 REAL Mode-A-eligible combos**
  (dagua engine X vs its OWN correct reference, >= MIN_MODE_SEEDS matched seeds). These are genuine
  matched pairs to start with.
- Corruption: `permute_reference_labels` (analysis.py:971), invoked at analysis.py:760-761 when
  `chance_permute=True`. It takes the reference's per-seed layouts and **re-orders the seed labels by a
  deterministic permutation** (`rng.permutation(len(seeds))`, purpose `r70::chance::<combo>`). The SET
  of reference layouts is unchanged; only which dagua-seed is paired against which reference-seed is
  scrambled. So a "chance" layout is NOT random and NOT a different graph's layout — it is the *correct
  reference cloud with the matched-seed correspondence destroyed*. This kills seed-tracking (gate4 KS
  on `p_track` + recovery_at_1) while leaving the marginal metric distributions identical.
- Why this design: it is the tightest possible adversary for the SEED-TRACKING claim (rungs 0/1). For
  the QUALITY claim it is weaker (the marginal stress/cross/np distributions are by construction the
  same as the real pair), which is exactly why it stresses the 3Q gate — see Q2.

### NEGATIVE control (gate3) — "wrong engine's layout"
- Selection: `select_negative_controls` (analysis.py:1742). For each graph it pairs dagua engine X's
  reimpl cloud against a **DIFFERENT engine's reference** (`other_ref`), i.e. a genuinely wrong target
  layout (e.g. `classic_neato` reimpl vs `graphviz_fdp` reference). Encoded as `(graph, "engine\tother_ref")`.
- Guards that make it a *fair-but-wrong* control (all must hold):
  - different algorithm token (analysis.py:1782) and different ref base (1784) — not the same algo in disguise;
  - `reimpl_cloud_informative` (1872): dagua's own cloud mean plain W_D <= 1.0 (cloud isn't itself degenerate);
  - `reference_distance_ok` (1913): the two references differ by Procrustes > 0.1 (the wrong target is
    actually a *different* layout, not a coincidental twin).
- So a negative-control "chance layout" = a real, high-quality layout produced by the *wrong algorithm*.

### Gates that consume them
- gate3 `evaluate_gate_negative` (report.py:2293): >= 95% must land in NON-primary rungs (not 0/1/2/2')
  + raw tracking bounded. **Currently 90% -> FAILS** (2/20 leak into a primary distributional rung).
- gate4 `evaluate_gate_chance` (report.py:2325): `p_track` KS-uniform (ks_p>0.01) + recovery_at_1 in
  [8,33]. Currently passes (ks_p=0.82, recovery=21).
- gate5 `evaluate_gate_quality_identical_laundering` (report.py:2353): the HARD 3Q line — over all 40
  negative+chance rows, `final_rung=='3Q'` must be <= 5%. **Currently 0/40 = 0.0% (clean).** This is the
  gate that any quality-equivalence rule must survive.

## Q2. WHY A CRUDE PARITY RULE PASSES 22/40 — ARTIFACT vs NON-DISCRIMINATIVE
================================================================================

### Reproduced exactly
A "FULL_PARITY" rule = D <= 1.05*R on all three battery means (stress lower-better, crossings
lower-better, np higher-better => D >= R/1.05) gives **22/40** — matching the r74_O6 figure. (The
Procrustes-aggregate variant `mean_W_D <= 1.05*mean_W_R` gives 32/40; the strictest D<=1.0R gives 8/40.
All > the 0% bar.)

### ROOT CAUSE = (a) NON-DISCRIMINATIVE METRICS, decisively — NOT mis-constructed controls.
The controls are constructed correctly (the wrong/shuffled layouts ARE wrong: negative refs differ by
Procrustes>0.1; chance refs have scrambled tracking, `p_track` significant). The parity rule passes
anyway because on these combos the *quality metrics cannot separate a true match from a wrong one*:

Audit of the 22 passers (recomputed):
- **ALL 40 controls sit on a STOCHASTIC reference**: ref self-spread `mean_W_R` ranges 0.234–1.38
  (chance) / 0.28–1.32 (negative). There is NO canonical reference layout. When the reference cloud's
  own seed-to-seed spread is ~0.5–1.0, dagua's distance to a *shuffled or wrong* reference is the same
  ~0.5–1.0 — Procrustes parity is automatic and meaningless. (`grid_20x20`, `dependency_500`,
  `powerlaw_500` all show W_D/W_R ~ 1.00 against a permuted ref.)
- **Metric saturation** on the passers: 6/22 have np_R >= 0.999 (neighborhood preservation pinned at
  1.0 — every layout is "perfect"); 2/22 have cross_R == 0 (no crossings to disagree about). On a
  saturated metric, D == R trivially for any layout including a wrong one.
- The parity rule is comparing aggregate means; on a stochastic engine the *marginal* stress/cross/np
  distributions of any competent layout are near-identical, so means match regardless of correspondence.

This is case (a): the metrics are genuinely non-discriminative on these (dense / disconnected /
stochastic-reference) graphs. The fix is therefore NOT to loosen the gate; it is to **exclude
non-discriminative combos from quality-eligibility**.

### WHY THE STRICT BATTERY ALREADY RESISTS THIS (0/40)
The registered battery is NOT a mean-parity rule. It is a **per-seed PAIRED/one-sample TOST** on
`stress_D - stress_R`, `cross_D - cross_R`, `np_D - np_R` (analysis.py:1167-1178), with absolute
margins (2%*mean stress, max(2%*cross_R,0.5), 0.02 np), combined as an IUT (max-p, analysis.py:1351),
then **BH-FDR across the whole family** (report.py:436) and gated at q<0.05.
- Permuting the reference labels (chance) destroys the per-seed pairing -> inflates the paired-difference
  variance -> TOST p goes UP (harder to pass), even though the means are unchanged. Recomputed binding
  (max-p) component across all 40: stress 26, cross 13, np 1 — the per-seed test catches them.
- Only 2/40 chance controls raw-pass all three components (`dependency_500::fr_steps500`,
  `scale_free_ba_120::sgd2_lr01`), and **even those never reach 3Q**: in `assign_rung` (distributional_fidelity.py:383-391)
  Mode-A checks `dist_equiv` BEFORE `quality_identical`, so both land in **rung 2** (they pass
  distributional equivalence) and are never quality-tested. 3Q is structurally a *fallback only for rows
  that already failed rungs 0/1/2*. Net: gate5 = 0/40.

So the architecture's safety comes from THREE compounding layers: (i) per-seed paired test (not mean
parity), (ii) BH-FDR across the family, (iii) rung ordering that diverts distributionally-equivalent
rows to rung 2 before 3Q is ever considered.

## Q3. A PRINCIPLED QUALITY-EQUIVALENCE CERTIFICATION
================================================================================

GOAL: certify genuine FP-floor as quality-equal; pass 0/40 controls; EXCLUDE genuine quality gaps
(sugiyama 22344 vs 2805 crossings).

### Is it possible? YES as a *design*, but on the CURRENT data it certifies ZERO additional combos —
### and that zero is the HONEST answer, not a failure of the design.

### The test (two stages):

**Stage 1 — per-combo DISCRIMINABILITY PRE-SCREEN (eligibility).** A combo may be quality-certified
only if its metrics CAN separate a right layout from a wrong one. Concretely a combo is eligible iff:
1. **Canonical reference exists / low ref self-spread.** `mean_W_R <= SPREAD_MAX` (recommend 0.15) for
   Mode A, or `near_deterministic` for Mode B. Rationale: if the reference cloud's own spread is large,
   no quality argument is possible (you can't out-resolve chance). This single criterion is the lever:
   ALL 40 controls have `mean_W_R >= 0.234`, so at SPREAD_MAX<=0.20 **0/40 controls are even eligible**.
2. **No saturated metric.** Exclude combos where np_R >= 0.999 AND cross_R == 0 (both discriminators
   dead). Optionally require the reference to exhibit non-trivial cross_R or sub-1.0 np_R.
3. (Optional, strengthens) **Margin >> reference self-noise.** Require the battery margin to exceed the
   reference's own metric SD, so "equal" means "within reference reproducibility," not "within noise."

**Stage 2 — the EXISTING strict battery** (per-seed paired TOST + IUT + BH-FDR, q<0.05), unchanged,
applied only to Stage-1-eligible combos, and only as the rung-4-fallback it already is.

### Why this excludes genuine quality gaps (sugiyama) automatically:
Sugiyama rung-4 rows are Mode-B near-deterministic (canonical ref) so they PASS Stage 1 — and that's
fine, because Stage 2 correctly rejects them: recomputed, all 231 sugiyama rung-4 rows have
`cross_p_tost = 1.0` (e.g. ba_2000 crD=1.91M vs crR=2.11M, a ~200K gap >> margin). 0/231 raw-pass the
battery. The crossing gap IS the quality gap and the strict per-seed test sees it. No pre-screen needed
to catch sugiyama; the battery already does.

### Validation against the 40 controls (all recomputed here):
- Stage-1 alone removes 40/40 controls from eligibility at SPREAD_MAX<=0.20 (all sit on stochastic
  refs). -> gate5 trivially 0/40.
- Stage-1 + Stage-2: 0/40 certified. PASS.
- Non-vacuity check (does it admit REAL combos?): 91/574 rung-4 rows have a discriminative reference
  (`mean_W_R<=0.15`) and WOULD be Stage-1-eligible — so the screen is not a tautology that blocks
  everything. But **0/91 pass the Stage-2 raw battery** -> 0 certified. The dry well is real.
- The "equal-quality but uncertifiable" FP-floor tail (drl/umap/neato, 15 rows) is, as O6 claimed,
  near-floor in QUALITY — BUT 0/15 have a discriminative reference (all `mean_W_R >= 0.168`, 13/15 >0.3).
  They live in exactly the non-discriminative bucket where Stage 1 (correctly) refuses to certify. You
  cannot tell their FP-floor from chance, because the controls prove chance looks identical there.

### Bottom line on Q3:
A principled certification = **discriminability pre-screen (low ref self-spread + non-saturated metrics)
THEN the existing strict per-seed battery**. It provably passes 0/40 controls, provably excludes sugiyama
(via the battery's crossing test), and is non-vacuous in principle (admits 91 eligible rung-4 rows).
On today's data it certifies **0 additional combos** — because the only rung-4 rows with equal *quality*
are those whose references are stochastic, where equal-quality is indistinguishable from chance by
construction, and the only rows with canonical references have real quality gaps. **Zero is correct.**
Do NOT add a parity/D<=R rule: it is the r73 trap (22/40), driven by metric non-discriminability, not by
control mis-construction.

quality gate (gate5 clean). Worth a look as a gate-3 calibration item, but it is not a laundering hole
