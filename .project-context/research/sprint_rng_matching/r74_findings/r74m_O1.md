# r74m O1 -- Audit of the kNN / neighborhood-preservation ("np") quality metric

## Bottom line

The `np` quality metric is **basin-INVARIANT by construction** -- it does NOT compare
dagua's spatial neighborhoods to the reference's spatial neighborhoods. It measures, for
EACH layout independently, how well that layout's own Euclidean nearest neighbors recover
the GRAPH's shortest-path neighbors, then compares the two scalar scores. It is reflection-,
rotation-, translation-, and scale-invariant. **So the feared artifact (a positional metric
masquerading as a quality gate) is NOT present in `np`.**

However, the audit surfaced TWO corrections that matter more than the original hypothesis:

1. **O6's premise is wrong.** `np` is NOT the universal binding constraint. Among rung-4
   combos, **stress** is the binding (max-p) quality constraint in 508/574; crossings in 43;
   `np` in only 19. Across the full quality battery (3692 combos), failing-metric counts are
   stress 1828, cross 1075, **np 400 (the LEAST)**.
2. The `np` failures that DO occur are **not evidence of a dagua quality deficit** -- the
   directional gap is centered near zero and, where np binds, dagua is on average BETTER.
   The real issue is a **margin/variance mismatch**, not a real algorithmic difference and
   not a basin artifact.

## What `np` ACTUALLY computes (file:line)

Field origin: `np_D_mean`, `np_R_mean`, `np_p_tost`, `np_margin` are produced in
`scripts/definitive_fidelity_analysis.py`:
- `quality_metric_samples` (lines 1283-1290): for each seed layout,
  `np_d = neighborhood_preservation(layout_dagua, dists, k=10)` and
  `np_r = neighborhood_preservation(layout_reference, dists, k=10)`.
  **Both sides are scored against the SAME graph-distance matrix `dists`.** Dagua's coords
  are never compared to reference coords here.
- TOST: `compute_mode_a_quality_battery` line 1175-1178 paired TOST on
  `metrics["np_d"] - metrics["np_r"]` with absolute margin `QUALITY_NP_ABS_MARGIN = 0.02`
  (line 51); mode B one-sample TOST line 1223.
- Record fields emitted: `quality_battery_record` lines 1368-1372.

The kernel: `neighborhood_preservation` in `dagua/eval/equivalence_metrics.py` lines 481-525:
```
pos = as_float64_positions(positions)              # 503  no alignment to any reference
layout_distances = _pairwise_distances(pos)        # 508  layout's OWN Euclidean dists
for node:
    graph_row = all_pairs_distances[node]          # 511  GRAPH shortest-path dists
    graph_neighbors = top-k of graph_row           # 519  k=10 graph neighbors
    layout_neighbors = top-k of layout_row         # 520  k=10 layout neighbors
    scores.append(|graph_nbrs & layout_nbrs| / k)  # 524  overlap fraction
return mean(scores)                                # 525  in [0,1]
```
`_pairwise_distances` (equivalence_metrics.py 987-1001) is a plain Euclidean distance matrix
on a single layout -- no cross-layout term. `as_float64_positions` (line 63) does dtype/shape
coercion only, **no Procrustes / no reference**. So the input coords are raw, and the metric's
own pairwise-distance basis makes it invariant to any rigid transform or reflection of the
layout. **Confirmed basin-invariant.**

(Contrast: the genuinely basin-SENSITIVE machinery -- `recovery_at_1`, `twin_rank_*`,
`p_track` from `_tracking_stats` (distributional_fidelity.py 817-851) -- operates on a
Procrustes cross-distance matrix `b_mat` built by `pairwise_procrustes_matrix` / `analyze_mode_b`
(lines 26, 108-178). That is the LAYOUT-stage positional test (rungs 1/2/3) and is SUPPOSED
to be positional. It is a different metric from `np` and is not the quality gate in question.)

## Artifact-or-real verdict: NEITHER basin-artifact NOR real deficit -- it's a MARGIN artifact

Empirical, from `eval_output/fidelity_definitive_r73/per_combo.json` (574 rung-4 combos):

- np gap (np_D_mean - np_R_mean): **mean +0.0243, median +0.0013, sd 0.129.**
  Centered on zero; if anything dagua is marginally higher (better). Only **30%** have
  dagua worse. Percentiles[5,25,50,75,95] = [-0.106, -0.004, +0.001, +0.028, +0.206].
  -> Rounding chaos averaging out is exactly what this looks like. No systematic deficit.
- Absolute np level ~0.62-0.64 (k=10 overlap fraction). The **0.02 ABSOLUTE margin is ~3%**
  of the level, and is **tiny relative to the per-combo gap sd (0.129)**. Equivalence
  (TOST) can fail whenever dagua and reference land in different basins of EQUAL quality,
  because different basins legitimately produce np scores that differ by >0.02 even though
  both are good -- the metric is invariant to the basin's POSE but not to which (equal-quality)
  basin you fell into.
- Where np actually binds (19 combos): gap **mean +0.063, median +0.034, dagua-worse only 27%.**
  These FAIL the equivalence test while dagua is BETTER on average. A quality gate that
  rejects "your layout preserves graph neighborhoods better than the reference" is mismeasuring.
- 22/574 rung-4 combos have |mean np gap| < 0.02 yet still fail np TOST (e.g.
  `long_range_residual_ladder::classic_sfdp_*`, `compound_dag_5x30::classic_fmmm_steps200`)
  -- the paired per-seed variance, not the mean, drives the failure.

So: **NOT a basin-sensitivity artifact** (the metric is invariant), and **NOT evidence of a
real dagua quality regression** (gap ~0, slightly favoring dagua). It is a **margin-calibration
artifact**: a fixed 0.02 absolute equivalence margin is too tight given (a) the metric's intrinsic
seed-to-seed variance and (b) the fact that equal-quality-but-different basins produce np values
differing by more than 0.02. The np TOST therefore reports "not equivalent" for combos whose np
QUALITY is genuinely indistinguishable in aggregate.

This is consistent with the project lead's logic: rounding cannot systematically reduce quality.
The np MEAN confirms it doesn't (gap ~0). The TOST failure is a property of the GATE (margin
vs variance), not of the layouts.

## Corrected, basin-invariant quality metric

The metric formula needs no change (it is already basin-invariant). The GATE needs recalibration.
Recommended, in priority order:

1. **Replace the fixed absolute margin with a variance-aware / relative margin.** Mirror what
   stress already does: `quality_stress_margin` derives the margin from `stress_r` (relative).
   Define `np_margin = max(NP_ABS_FLOOR, NP_REL_FRAC * np_r_mean)` or, better, scale to the
   reference's own seed-to-seed np dispersion: `margin = z * sd(np_r over seeds)` (e.g. a
   tolerance of one reference-population sd). This makes "equivalent" mean "within the
   reference's own basin-to-basin spread," which is the correct null for FP-floor combos.
2. **Use a non-inferiority (one-sided) test, not two-sided TOST, OR symmetric-but-honest.**
   Since rounding cannot reduce quality, the scientifically meaningful question is
   "is dagua's np NOT WORSE than reference by more than delta." A one-sided non-inferiority
   bound stops penalizing combos where dagua is BETTER (the 19 binding cases, 73% of which
   favor dagua). If two-sided is kept for symmetry, widen the upper margin so "better" never
   fails.
3. **Aggregate-over-seeds population equivalence, not paired diff.** The paired TOST assumes
   seed i of dagua and seed i of reference are the same draw; under basin chaos they are not
   paired in any meaningful way. A two-sample / distributional equivalence on the np
   POPULATIONS (e.g. equivalence on the means with the energy/TOST machinery already in the
   file) better matches "indistinguishable in aggregate over 100 seeds."

All three preserve basin-invariance and pass the anti-laundering controls because they tighten
the NULL to "equal quality distribution," not "equal positions" -- they do not relax toward
accepting genuinely worse layouts (option 1/3 still reject a true downward shift; option 2
only stops penalizing improvements).

## Confidence

- That `np` is basin-invariant by construction: **very high** (read every line of the kernel
  and its inputs; no reference coords, no alignment, single-layout distance basis).
- That np is NOT the universal binding constraint (stress dominates): **very high** (direct
  count over 574 rung-4 + 3692 full-battery combos).
- That np failures are margin/variance artifacts rather than real deficits: **high** (gap
  centered at zero, slightly favoring dagua; binding cases favor dagua 73%).
- That the proposed recalibration is the right fix: **medium-high** -- direction is clearly
  right (gate, not formula); exact margin form (rel-fraction vs reference-sd vs two-sample)
  should be chosen by re-running the anti-laundering controls (0/40 must hold) under each.
