# R74M CX5 empirical quality audit
Input: `/tmp/r74m_cx_shared.md`. Output from existing stored layouts only; no benchmark reruns. I overlaid all `eval_output/benchmark_100seed_*` stores by `results.json` mtime, matching the newest-dir-per-record warning. Intermediate numeric dump: `/tmp/r74m_CX5.json`.
## Method
- Selected seven connected Mode A rung-4 rows across GEM/FMMM/SFDP, plus two Sugiyama Graphviz-fidelity contrast rows. Sugiyama contrasts are Mode B in r73: 100 dagua seeds against one deterministic Graphviz-dot reference, not 100 reference seeds.
- Stress is `distributional_fidelity.stress_per_layout`: closed-form fitted-scale normalized stress. Crossings were exact segment counts in the temp script for these small selected graphs; this avoids the slow project `count_crossings` path and is valid for the selected small edge counts. NP is `equivalence_metrics.neighborhood_preservation(k=10)`.
- Margins: stress 5% of reference mean, crossings max(2% reference mean, 0.5), NP absolute 0.02. Verdict labels below use signed D-R means; lower is better for stress/crossings, higher is better for NP.

## Interpretation
- GEM FP-floor examples are not quality deficits. All three selected GEM rows are systematically better on fitted-scale stress; grid is also better on crossings and NP. The equivalence failure is a real quality offset, but in dagua's favor, not a floor-caused degradation. Reference variance is huge relative to the margin (e.g. binary-tree stress ref SD/margin 19.25), but the mean offset is also far outside the margin.
- FMMM has a real deficit on `deep_chain_20::classic_fmmm_steps10`: fitted-scale stress 0.14461 vs 0.03182 and NP 0.8065 vs 0.9829. This is not reference variance: the signed offsets are 70x and 8.8x their margins. `asymmetric_hourglass_hub::classic_fmmm_steps10` is mixed: fitted-scale stress worse, but crossings/NP within margin and exact unscaled stress flips in dagua's favor after similarity alignment.
- SFDP selected rows are mixed. `asymmetric_hourglass_hub::classic_sfdp_default` has a small but systematic fitted-scale stress deficit (0.03005 vs 0.02666, diff 2.54x margin), while crossings and NP are balanced. `binary_tree::classic_sfdp_p_neg2` is quality-better despite rung 4. r73 also flags large SFDP p=-2 rows as serious quality deficits in the stored 60-seed battery (not recomputed here): `ba_500::classic_sfdp_p_neg2` battery stress D/R 23.2x relative worse and crossings +11854.6.
- Sugiyama contrasts are genuine Mode B gaps, not FP-floor Mode A. `asymmetric_hourglass_hub::classic_sugiyama_graphviz_fidelity` is worse on fitted-scale stress and NP (NP -0.100 on a 0.020 margin). `binary_tree` is worse only on fitted-scale stress. Exact unscaled stress favors dagua in both, so the enormous raw stress gap in r73 is a scale artifact, but the fitted-scale stress and NP gaps do not vanish after similarity alignment.

## More-Work Signals
- FMMM cause candidate: `dagua/layout/ops/fmmm.py` divides total fixed-iteration budget by hierarchy depth with a hard minimum (`fmmm_level_budget = max(10, steps // levels)`) and `classic_fmmm_steps10` therefore runs only 10 refinement steps per level; the force loop exits only on average-force threshold in OGDF-scaling mode. On chain-like graphs this under-refines topology, matching the deep-chain stress/NP deficit. See `dagua/layout/ops/fmmm.py:1723`, `dagua/layout/ops/fmmm.py:1415`, `dagua/layout/ops/fmmm.py:1418`.
- SFDP cause candidate: Graphviz-fidelity mode clamps p<-1 to -1 in code comments, but variants still declare `classic_sfdp_p_neg2` as p=-2; check whether reference and dagua are both using the same effective exponent in every path. Also the finest-level Graphviz refinement disables adaptive cooling after prolongation, so stress offsets can persist. See `dagua/layout/ops/pipelines/sfdp.py:426`, `dagua/eval/variants.py:1616`, `dagua/layout/ops/pipelines/sfdp.py:839`, `dagua/layout/ops/pipelines/sfdp.py:848`.
- Sugiyama cause candidate: the code itself names Graphviz dot network-simplex rank assignment, mincross, x-position simplex, and cluster metadata as residual architectural divergences. The measured NP gap on asymmetric-hourglass is consistent with ordering/coordinate assignment, not scale. See `dagua/layout/ops/pipelines/sugiyama.py:60`, `dagua/layout/ops/sugiyama.py:378`, `dagua/layout/ops/pipelines/sugiyama.py:114`.

## Scale Alignment Check
Procrustes+scale similarity does not change fitted-scale stress, crossings, or NP for these metrics. It does change the exact unscaled normalized stress used by the strict battery. Several exact-stress gaps flip in dagua's favor after alignment, so raw exact stress is contaminated by scale. Real gaps that remain are: FMMM steps10 deep-chain fitted stress/NP, SFDP default asymmetric fitted stress, Sugiyama asymmetric fitted stress/NP, Sugiyama binary-tree fitted stress.

## Concerns
- I did not recompute project `count_crossings` for large rows because the repeated project path was too slow. For selected small graphs I used exact segment intersections; for large `ba_500` I quote r73 stored battery means only.
- Sugiyama has no 100-seed reference distribution in the stored r73 rows inspected here; reference variance cannot explain those Mode B failures because the reference side is deterministic.
