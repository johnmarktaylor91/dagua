Fix a data-hygiene defect in dagua's fidelity analysis overlay: SEED-ERA FRANKENSTEIN MIXING.

THE BUG (confirmed by the sprint lead tonight): scripts/definitive_fidelity_analysis.py
load_results_multi() overlays benchmark dirs PER RECORD KEY (graph::engine::seedN). Old-era dirs
(e.g. benchmark_100seed_r73_fixes) contain rows at seeds 42-99 while new-era dirs
(benchmark_100seed_r75_fixes etc.) cover seeds 100-199. The union therefore MIXES layout rows
generated by DIFFERENT CODE VERSIONS into one combo battery: for
parallel_cycles_4x5::classic_classical_mds_igraph_fidelity the merged index holds 158 rows
(58 old pre-DLA + 100 new post-DLA), and the quality battery averaged stress ~1.0 old rows with
~0.011 new rows into D=0.555, wrongly keeping the combo divergent. A sweep shows THOUSANDS of
(graph, engine) combos across all families have mixed seed eras in the 11-dir chain.

THE FIX (approved direction): overlay resolution must be PER-COMBO FRESHEST-DIR-WINS. For each
(graph, engine): find the LAST directory in the --data-dir precedence order that contains at
least one usable ('ok') row for that combo, and use ONLY rows from that directory for it. Never
union rows for one combo across multiple dirs. This makes era mixing structurally impossible
while old dirs still provide combos absent from newer dirs. Partial fresh coverage (a newer dir
with fewer seeds) legitimately wins over a mixed union -- reduced n is honest, mixing is not.
