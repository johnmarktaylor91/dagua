## FR
Source: [fr.py](/home/jtaylor/projects/dagua/dagua/layout/classic/fr.py)

- `Steps:` validate inputs; choose output device; return early for `num_nodes==0`; initialize `positions` from `pos` or NumPy unit-square randoms; build dense directed `adjacency[N,N]`; set `optimal_distance=sqrt(1/N)`, `temperature=0.1*max(x_extent,y_extent)`, `cooling_step=temperature/(steps+1)`; each iteration computes dense pairwise `delta[N,N,2]`, `distance[N,N]`, FR displacement `k^2/d - A*d/k`, normalizes each node move to current temperature, updates positions, optionally records trace, cools temperature, and breaks on mean movement threshold; finally recenters/rescales to unit max-abs and multiplies by `sqrt(N)*50`.
- `Config params:` `edge_index: torch.Tensor`; `num_nodes: int`; `node_sizes: Optional[torch.Tensor]=None` unused; `steps: int=50`; `seed: int=42`; `area: Optional[float]=None` validated then ignored; `trace_every: int=0`; `pos: Optional[torch.Tensor]=None`; `edge_weights: Optional[torch.Tensor]=None`.
- `State/data:` solver state is `positions[N,2] float64` on CPU; `adjacency[N,N] float64` directed and dense; per-iter `delta`, `distance`, `displacement[N,2]`, `length[N]`, `delta_pos[N,2]`; traces store float32 copies on output device.
- `Solver:` hand-written synchronous FR force step; no optimizer object.
- `Convergence:` stops at `steps` or when `||delta_pos|| / num_nodes < 1e-4`.
- `Shared ops/motifs:` `RandomUniformInit`, exact all-pairs repulsion, edge attraction, temperature-style movement clamp, linear cooling, center+scale postprocess. Closest peers: GraphOpt, FA2, LGL.
- `Hardcoded candidates:` `MIN_DISTANCE=0.01`, `CONVERGENCE_THRESHOLD=1e-4`, `OUTPUT_SCALE_FACTOR=50`, initial-temperature factor `0.1`, fixed `optimal_distance=sqrt(1/N)`, final rescale target `1.0`, dense directed adjacency semantics.
- `RNG exactness:` if `pos` is given, no RNG is consumed. Otherwise it creates `np.random.RandomState(seed)` and makes exactly one call, `rand(num_nodes, 2)`, consuming `2*num_nodes` uniform draws from that private NumPy MT19937 stream. No later randomness.

## FA2
Source: [fa2.py](/home/jtaylor/projects/dagua/dagua/layout/classic/fa2.py)

- `Steps:` validate; early-return for `N=0/1`; collapse `edge_index` to unique undirected non-self edges and optionally sum reciprocal/parallel weights; compute `masses = undirected_degree + 1`; compute outbound-attraction compensation as mean mass when enabled; initialize `pos[N,2]` from Python `random.random()` in `[0,1)`; initialize `speed`, `speed_efficiency`, `jitter_tolerance`, `old_force`; for each step compute repulsion by exact all-pairs or Barnes-Hut quadtree, add gravity, add attraction over unique undirected edges, adapt speed from swinging/traction, apply movement, save `old_force`, optionally trace.
- `Config params:` `edge_index`; `num_nodes: int`; `node_sizes: Optional[torch.Tensor]=None` unused; `steps: int=100`; `seed: int=42`; `gravity: float=1.0`; `scaling_ratio: float=2.0`; `linlog: bool=False`; `strong_gravity: bool=False`; `trace_every: int=0`; `outbound_attraction_distribution: bool=True`; `edge_weights: Optional[torch.Tensor]=None`; `dissuade_hubs: bool=False`; `edge_weight_influence: float=1.0`; `barnes_hut: bool=False`; `barnes_hut_theta: float=1.2`.
- `State/data:` `pos[N,2] float32` on input device; `undirected_edges[2,E_u]`; `undirected_weights[E_u]` optional; `masses[N]`; `force[N,2]`, `old_force[N,2]`; scalar `speed`, `speed_efficiency`; Barnes-Hut nodes store `mass_center_x`, `mass_center_y`, `mass`, `size`, `children`, `indices`.
- `Solver:` explicit ForceAtlas2 integrator with global adaptive speed; Barnes-Hut path builds/traverses quadtree inside the repulsion routine.
- `Convergence:` fixed `steps` only.
- `Shared ops/motifs:` `GravityToOrigin`, `BarnesHutForce`, `AdaptiveSpeedApply`, undirected-edge preprocessing, spring attraction, exact pairwise repulsion fallback. Closest peers: FR, GEM.
- `Hardcoded candidates:` `jitter_tolerance=1`, initial `speed=1`, `speed_efficiency=1`, several FA2 control constants inside `_adjust_speed_and_apply_forces` (`0.05`, `10`, `2`, `0.5`, `0.7`, `1.3`, speed cap `1000`), strong-gravity axis check, self-loop dropping and undirected dedupe policy.
- `RNG exactness:` for `N>1`, it imports module `random` as `_random`, calls `_random.seed(seed)`, then calls `_random.random()` twice per node in list-comprehension order `(x, y)`. That is the only RNG path; it mutates Python’s module-global RNG state. Barnes-Hut and all later steps are deterministic.

## GEM
Source: [gem.py](/home/jtaylor/projects/dagua/dagua/layout/classic/gem.py)

- `Steps:` validate; early-return for `N=0/1`; cap `max_iters` at `30000`; compute final `extent`; branch on `N<=5000`. Small-graph path: initialize normal random positions on CPU, degree weights, node desired lengths (`diagonal + 20`), weighted undirected adjacency, local temperatures, previous impulses, skew gauge, weighted barycenter; repeatedly draw a seeded random permutation when exhausted, pop one node, compute that node’s gravity + full repulsion + edge attraction impulse, update that node in-place with local temperature and OGDF oscillation/skew rules, update barycenter/global temperature. Large-graph path: initialize device positions, temperatures, skew state; each step computes sampled or exact batched repulsion, batched attraction, barycenter gravity, scales movement by per-node temperature, updates temperatures vectorially, and moves all nodes synchronously; both paths end with normalization.
- `Config params:` `edge_index`; `num_nodes: int`; `node_sizes: Optional[torch.Tensor]=None` affects desired lengths and final extent; `max_iters: int=500`; `seed: int=42`; `edge_weights: Optional[torch.Tensor]=None`.
- `State/data:` sequential path uses `positions[N,2] float64 CPU`, `degree_weights[N]`, `node_desired_lengths[N]`, `adjacency: list[list[(neighbor, weight)]]`, `local_temperatures[N]`, `previous_impulse[N,2]`, `skew_gauge[N]`, `barycenter[2]`, `permutation: list[int]`, scalar `global_temperature`; batched path uses `positions[N,2]`, `temperatures[N]`, `previous_impulse[N,2]`, `skew_gauge[N]`, `repulsive/attractive/gravity/impulse/movement[N,2]`.
- `Solver:` OGDF-style GEM. Small graphs use sequential Gauss-Seidel node ticks; large graphs use a documented synchronous fallback.
- `Convergence:` sequential path stops when `global_temperature <= 0.005` or iteration budget exhausted; batched path stops when `mean(temperatures) < 0.005` or budget exhausted.
- `Shared ops/motifs:` `RandomNormalInit`, per-node temperature annealing, barycenter gravity, attraction/repulsion force sum, normalization. Closest peers: FA2, FR, LinLog.
- `Hardcoded candidates:` `_SEQUENTIAL_NODE_LIMIT=5000`, `_FULL_REPULSION_LIMIT=2000`, sampled neighbors `96`, round cap `30000`, `_INITIAL_TEMPERATURE=12`, `_MINIMAL_TEMPERATURE=0.005`, `_GRAVITATIONAL_CONSTANT=1/16`, `_DESIRED_LENGTH=20`, degree divisor `2.5`, oscillation/rotation sensitivities and thresholds, `_ATTRACTION_FORMULA=1`. `_rotate_impulse()` is present but not used by the live algorithm path.
- `RNG exactness:` initialization always creates `torch.Generator(device="cpu")`, `manual_seed(seed)`, then calls one `torch.randn((num_nodes, 2), generator=generator)`. Small-graph path then creates a second CPU generator with the same seed and calls `torch.randperm(num_nodes, generator=generator)` each time the permutation list empties; `pop()` consumes that permutation in reverse list order. Large-graph path uses no persistent RNG after init; when sampled repulsion is active it creates a fresh CPU generator per step, seeds it with `seed + step + 1`, then makes one `torch.randint(0, num_nodes, (num_nodes, sample_size), generator=generator)` call. `_rotate_impulse()` does not run, so its `torch.rand` does not consume seed state.

## GraphOpt
Source: [graphopt.py](/home/jtaylor/projects/dagua/dagua/layout/classic/graphopt.py)

- `Steps:` validate; choose device; early-return for `N=0`; initialize CPU `positions` from Python randoms; filter non-self spring edges while preserving multiplicity/order; precompute all unordered node pairs with `torch.triu_indices`; for each iteration zero `forces`, add Coulomb repulsion for pairs within distance cap, add per-edge spring force with rest length and optional weight scaling, divide by `node_mass`, clamp each axis to `[-max_sa_movement, max_sa_movement]`, update positions; cast to float32/device.
- `Config params:` `edge_index`; `num_nodes: int`; `node_sizes: Optional[torch.Tensor]=None` unused; `seed: int=42`; `niter: int=500`; `node_charge: float=0.001`; `node_mass: float=30.0`; `spring_length: float=0.0`; `spring_constant: float=1.0`; `max_sa_movement: float=5.0`; `edge_weights: Optional[torch.Tensor]=None`.
- `State/data:` `positions[N,2] float64 CPU`; `spring_edges[2,E_clean]`; `spring_weights[E_clean]` optional; `pair_source[P]`, `pair_target[P]`; `forces[N,2]`; temporary `delta`, `distance_sq`, `distance`, `movement`.
- `Solver:` explicit synchronous force summation with hard per-axis movement clamp; no optimizer object.
- `Convergence:` fixed `niter` only.
- `Shared ops/motifs:` `RandomUniformInit`, exact pairwise repulsion, spring attraction, movement clamp. Closest peers: FR.
- `Hardcoded candidates:` Coulomb constant `8_987_500_000`, repulsion cutoff `500`, `_MIN_DISTANCE=1e-12`, spring magnitude uses `0.5 * spring_constant * abs(distance - spring_length)`, axiswise clamp instead of vector clamp.
- `RNG exactness:` if `N>0`, it creates a private `random.Random(seed)` and calls `rng.random()` twice per node in `(x, y)` order. No later random calls.

## LinLog
Source: [linlog.py](/home/jtaylor/projects/dagua/dagua/layout/classic/linlog.py)

- `Steps:` validate; early-return for `N=0/1`; initialize normal random coordinates and mark them `requires_grad`; derive `initial_lr=min(0.05, 0.8/N)` and `final_lr=max(initial_lr*0.1, initial_lr/sqrt(steps))`; create `torch.optim.Adam`; for each step zero grads, compute LinLog loss as edge attraction plus exact or sampled all-pairs repulsion, backprop, `optimizer.step()`, then linearly decay the learning rate; normalize at the end.
- `Config params:` `edge_index`; `num_nodes: int`; `node_sizes: Optional[torch.Tensor]=None` only affects final extent; `steps: int=300`; `seed: int=42`; `a: float=1.0`; `r: float=0.0`; `edge_weights: Optional[torch.Tensor]=None`.
- `State/data:` trainable `positions[N,2]`; exact repulsion uses `pair_src`, `pair_dst` from `torch.triu_indices`; sampled repulsion uses concatenated sampled source/target tensors plus `total_pairs`; scalar `loss`; Adam state in optimizer param groups.
- `Solver:` Adam on node coordinates with deterministic linear LR decay.
- `Convergence:` fixed `steps` only.
- `Shared ops/motifs:` `RandomNormalInit`, `LinLogAttractionLoss`, `LinLogRepulsionLoss`, `AdamStep`, `LRDecay`, `NormalizePositions`. Closest peer: GEM.
- `Hardcoded candidates:` exact/sampled switch at `2000`, sampled-neighbor factor `128`, max `8` sampling rounds, `_MIN_DISTANCE=1e-3`, LR heuristics, extent heuristic, sampled estimator keeps duplicate pairs instead of deduping.
- `RNG exactness:` initialization uses a private CPU `torch.Generator` seeded with `seed`, then one `torch.randn((num_nodes, 2), generator=generator)`. For `N>2000`, each optimization step creates a fresh CPU generator seeded with `seed + step + 1`; each sampling round then calls `torch.randint(...)` for `src` first and `torch.randint(...)` for `dst` second. If `sample_size==0` or `sample_size==total_pairs`, no `torch.randint` calls occur for that step.

## DRL
Source: [drl.py](/home/jtaylor/projects/dagua/dagua/layout/classic/drl.py)

- `Steps:` validate; choose device; early-return for `N=0`; resolve preset/override parameters; build symmetric weighted adjacency map; initialize positions uniformly on CPU; build one `_DensityGrid` and add all nodes; initialize a second seeded Python RNG for perturbations plus edge-cut schedule scalars; iterate phases in order `init`, `liquid`, `expansion`, `cooldown`, `crunch`, `simmer`; inside each phase mutate `temperature`, `attraction`, `min_edges`, `cut_off_length`, and `damping_mult` by hardcoded per-iteration schedules; for each node remove it from the density grid, evaluate current energy, compute weighted-neighbor centroid, compute analytic damped move, optionally cut one long edge in `expansion/cooldown`, sample one random perturbation around the analytic point, evaluate analytic and perturbed energies, keep the best of current/analytic/perturbed, then reinsert into the density grid.
- `Config params:` public signature is `edge_index`; `num_nodes: int`; `node_sizes: Optional[torch.Tensor]=None` unused; `seed: int=42`; `edge_weights: Optional[torch.Tensor]=None`; `options: str | Mapping[str, object] | object = "default"`. Default preset is `edge_cut=0.8`, `init(0, 2000, 10, 1)`, `liquid(200, 2000, 10, 1)`, `expansion(200, 2000, 2, 1)`, `cooldown(200, 2000, 1, 0.1)`, `crunch(50, 250, 1, 0.25)`, `simmer(100, 250, 0.5, 0)` where each tuple is `(iterations:int, temperature:float, attraction:float, damping_mult:float)`. Mapping/object overrides use keys like `liquid_iterations`, `simmer_temperature`, plus `edge_cut`.
- `State/data:` `adjacency: list[dict[int, float]]`; `positions[N,2] float64 CPU`; `_DensityGrid` fields are `density[grid,grid]`, `node_cells: dict[int,(x,y)]`, `buckets: dict[(x,y), set[int]]`, `kernel[(2r+1),(2r+1)]`, `cell_width`, `origin`; phase vars `temperature`, `attraction`, `damping_mult`, `fine_density`, `min_edges`, `cut_off_length`.
- `Solver:` greedy sequential local search, not gradient descent: it compares three candidate positions per node against an energy with density penalties and neighbor attraction.
- `Convergence:` none beyond phase iteration counts.
- `Shared ops/motifs:` preset-driven `PhaseSchedule`, density-grid repulsion proxy, weighted adjacency preprocessing, sequential node updates. Closest peers: LGL for staged placement, FA2/GEM for temperature-style control.
- `Hardcoded candidates:` `_GRID_SIZE=1000`, `_VIEW_SIZE=4000`, `_GRID_RADIUS=10`, `_FINE_REPULSION_SCALE=1e-4`, `_CUT_BASE=40000`, attraction factor scale `0.02`, stage powers `{4,2,1}`, random jump factor `0.01*temperature`, all per-phase decrement rates and floors.
- `RNG exactness:` there are two separate private `random.Random(seed)` instances. `_initialize_positions()` uses the first and calls `rng.random()` twice per node. `layout_drl()` then creates a second `random.Random(seed)` for perturbations; for every node update in every nonzero-iteration phase it calls `rng.uniform(-0.5, 0.5)` twice in `(x, y)` order to build `random_offset`. The two streams are independent because they are separate objects seeded identically.

## LGL
Source: [lgl.py](/home/jtaylor/projects/dagua/dagua/layout/classic/lgl.py)

- `Steps:` validate; resolve defaults for `maxdelta`, `area`, `repulserad`, `cellsize`; build unique undirected BFS adjacency plus multiplicity-preserving spring list; create a seeded Python RNG and choose `root` randomly if absent; compute `frk`, drawing `radius`, and initialize all positions uniformly in `[-radius, radius]`; place root at origin; BFS from root to obtain `layers` and `parents`; maintain `placed`, active spring edges, and incident-edge index lists; for each BFS shell place children around parent anchors using deterministic first-shell angles or later random directions, activate edges whose endpoints are now both placed, then run an FR-style refinement over all placed nodes so far using spring attraction, cell-bucket local repulsion, a cooling schedule, and an early break on small max movement; leave disconnected vertices at their original random positions.
- `Config params:` `edge_index`; `num_nodes: int`; `node_sizes: Optional[torch.Tensor]=None` unused; `seed: int=42`; `maxiter: int=150`; `maxdelta: Optional[float]=None` default `num_nodes`; `area: Optional[float]=None` default `num_nodes**2`; `coolexp: float=1.5`; `repulserad: Optional[float]=None` default `area*num_nodes`; `cellsize: Optional[float]=None` default `area**0.25`; `root: Optional[int]=None`; `edge_weights: Optional[torch.Tensor]=None`.
- `State/data:` `adjacency: list[list[int]]`; `spring_edges: list[(u,v)]` with multiplicity; `spring_edge_weights: list[float] | None`; `positions[N,2] float64`; BFS `layers: list[list[int]]`, `parents: list[int]`; `placed[N] bool`; `active_edges`, `active_edge_weights`, `edge_active[bool]`, `incident_edge_indices: list[list[int]]`; refinement buckets are `dict[(cell_x, cell_y), list[node]]`; `forces[N,2]`.
- `Solver:` BFS shell-growth initializer plus repeated FR-style local refinement on the currently placed subgraph; no optimizer object.
- `Convergence:` each refinement phase stops at `maxiter` or when `maxchange < 1e-5`.
- `Shared ops/motifs:` random uniform init, sparse-grid local repulsion, FR-like spring attraction, temperature movement clamp, BFS layering. Closest peers: FR and DRL.
- `Hardcoded candidates:` `_CONVERGENCE_EPSILON=1e-5`, root forced to origin, first shell placed on exact circle, deeper shells use normalized random square vectors, anchor `parent + center_direction + parent_direction`, harmonic shell scaling, repulsion formula `frk^2 * (1/d - d^2/repulserad)`, repulsion cutoff at `cellsize`.
- `RNG exactness:` one `random.Random(seed)` in `layout_lgl()` is used first for `rng.randrange(num_nodes)` when `root is None`, then later for shell-placement directions; each deeper-shell child consumes two `rng.uniform(-1, 1)` calls in `(x, y)` order. `_initialize_positions()` separately creates another `random.Random(seed)` and consumes two `rng.uniform(-radius, radius)` calls per node. Because the RNG objects are separate, random root choice does not perturb the initial-position stream.

## Cross-Algorithm Patterns
- Every file starts with strict input validation and an explicit device choice, but most classic solvers actually do their core math on CPU and only cast to output device at the end.
- Initialization falls into two families: uniform random (`FR`, `FA2`, `GraphOpt`, `DRL`, `LGL`) and normal random (`GEM`, `LinLog`).
- Edge preprocessing has two incompatible motifs: deduped undirected structure for FA2/DRL/GEM, versus multiplicity-preserving spring lists for GraphOpt/LGL, while FR keeps the original directed dense adjacency.
- Scalable repulsion is handled four different ways: exact all-pairs (`FR`, `GraphOpt`, small `FA2`, small `LinLog`), Barnes-Hut (`FA2`), deterministic random sampling (`GEM`, `LinLog`), density/cell proxies (`DRL`, `LGL`).
- Only `LinLog` uses a standard optimizer (`Adam`); the rest are custom steppers with temperature, speed, damping, or greedy candidate selection.
- Convergence is usually weak: `GraphOpt`, `FA2`, `LinLog`, and `DRL` are fixed-budget; `FR`, `GEM`, and `LGL` add a simple movement/temperature threshold.
- Randomness is almost always front-loaded into initialization plus one extra stochastic component: permutations in `GEM`, sampled pairs in `LinLog`, jitter in `DRL`, shell directions in `LGL`. After that, dynamics are deterministic.
- `node_sizes` is mostly ignored; only `GEM` uses it materially for desired lengths and scaling, and `LinLog` uses it only for final extent.
